# Вайб-радар — Telegram-канал о нашумевших AI и вайб-кодинг проектах

Автономная редакция канала: каждый час ищет AI-проекты, которые прямо сейчас взрывают интернет, измеряет скорость их роста, оценивает хайп по шкале 1–10 и сама публикует посты. Вечером выходит дайджест дня.

Устроен так же, как [russia-nato-monitor](https://github.com/Igoryanich/russia-nato-monitor): Node 24 + TypeScript без сборки, SQLite в ветке `state`, Gemini с цепочкой моделей и фоллбэком, GitHub Actions. Работает бесплатно, компьютер не нужен. Редакционные правила — в [prompts/system.md](prompts/system.md).

## Как это работает

```
~30 источников: GitHub Trending + молодые репозитории (Search API), Hacker News (Algolia),
Reddit (9 сабреддитов), Hugging Face trending, Product Hunt, Bluesky, пресса (RSS)
 → одна вещь на разных площадках = один проект (репо + Show HN + тред на Reddit + Space)
 → снимки счётчиков каждый час → прирост звёзд/очков/апвоутов за 24 и 72 часа    (код, без AI)
 → предварительный отбор: топ-30 самых быстрых AI-проектов
 → scan (Gemini): HYPE_SCORE 1–10, стадия, статус, риски, доступность из РФ
 → пороги проверяет код: пост при ≥7, или ≥6 + «ранний сигнал» + измеренная аномальная скорость
 → текст поста (Gemini) → жёсткие проверки → очередь → Telegram (автопостинг)
 → после 21:00 по Хельсинки — дайджест дня (закрепляется, вчерашний открепляется)
```

## Редакционные гарантии (проверяются кодом)

- **Скорость не угадывается.** Все дельты (`delta_24h`, `delta_72h`) считаются по нашим снимкам счётчиков. Модель видит, сколько часов реально покрыто наблюдением.
- **Цифры не выдумываются.** Каждое число ≥ 100 в тексте должно совпадать (±5%) с измеренным счётчиком. Иначе текст переписывается; если со второй попытки не вышло, пост не публикуется.
- **Ссылки только настоящие.** В пост попадают только URL, которые видели сборщики (репозиторий, сайт проекта, тред), и ссылки на наши же посты.
- **Пороги — в коде.** Слова модели «publish_post» недостаточно: код повторно проверяет балл, стадию и измеренную скорость.
- **Повтор — только с новостью.** Повторный пост выходит при росте главного счётчика в 3 раза или при новости (новая версия, скандал) не раньше чем через 48 часов. Публикуется ответом на исходный пост.
- **Формат.** Telegram HTML с белым списком тегов, баланс тегов, лимит длины (1800 знаков на пост, 3600 на дайджест), текст на русском.
- **Нагрузка.** Не больше 2 постов за цикл и 6 в день. Дайджест не выходит, если за день меньше 3 достойных проектов.

## Запуск

1. Создайте **публичный** репозиторий (например, `vibe-radar`) и загрузите туда этот проект. Публичный — чтобы минуты Actions были бесплатными и безлимитными.
2. Создайте бота в @BotFather и добавьте его админом канала с правами «Публикация сообщений» и «Закрепление сообщений».
3. В репозитории откройте **Settings → Secrets and variables → Actions**:
   - Secrets: `GEMINI_API_KEY` (лучше из отдельного Google Cloud проекта), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID` (`@имя_канала`).
   - Variables: `DRY_RUN` = `true` на первые сутки, `CHANNEL_NAME` = название канала.
4. Запустите workflow **radar** вручную (Actions → radar → Run workflow), затем он пойдёт сам каждый час.
5. Через сутки прочитайте, что бы вышло: в логе шага «Latest texts», или локально (`npm run posts`). Если устраивает, поставьте `DRY_RUN` = `false`.

Первые несколько часов постов почти не будет, и это нормально: для дельт за 24 часа нужны снимки за 24 часа. Сразу работают только GitHub Trending («N stars today»), свежие репозитории и свежие посты HN/Reddit, у которых весь счётчик набран внутри окна.

## Локально

```bash
npm install
cp .env.example .env        # впишите GEMINI_API_KEY
npm run collect             # собрать источники
node src/cli.ts candidates  # что увидит scan: проекты, счётчики, дельты
node src/cli.ts scan        # оценка хайпа
node src/cli.ts projects    # вердикты
node src/cli.ts posts-queue # написать посты (в DRY_RUN не отправляются)
npm run posts               # прочитать тексты
npm run check               # typecheck + тесты
```

## Чего нет

- **X/Twitter, TikTok, Instagram, Discord.** У них нет бесплатного стабильного API. Их охват виден косвенно: через упоминания в прессе и Bluesky и через треды Reddit со ссылками на видео.
- **Веб-поиска при оценке.** Модель работает только с собранными данными. Так её выводы проверяемы, а цифры не придумываются.
- **Голоса Product Hunt.** RSS даёт только сам факт запуска; голоса доступны через API с токеном, его можно добавить позже.
